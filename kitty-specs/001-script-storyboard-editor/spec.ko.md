# 기능 명세서: 스크립트 & 스토리보드 에디터

**기능 브랜치(Feature Branch)**: `[001-script-storyboard-editor]`
**작성일**: 2026-01-02
**상태**: 초안 (Draft)
**입력**: 1단계: 주제 -> 스크립트 자동 생성(60초 이하 목표) -> 스토리보드 장면 카드(생성/편집). 이 기능은 다음을 수행합니다: 1) 옵션(플랫폼, 목표 시간, 비디오 유형)과 함께 주제 입력 접수, 2) 빠른 편집 기능(축소/확장/재구성/톤 변경)을 포함한 LLM을 이용한 스크립트 자동 생성, 3) 스토리보드 장면 생성(1회 분할, 60초 영상 기준 장면이 20개를 초과할 경우 자동 병합), 4) 장면 카드 편집 허용(길이, 키워드, 자막 프리셋), 5) 데이터 영속성 및 다시 불러오기.
**범위 제외**: 미디어 가져오기/제공자(providers), TTS/음성 합성, 렌더링/작업 대기열 구현.
**PRD 소스**: docs/AutoShorts_PRD.md

## 사용자 시나리오 & 테스트 (User Scenarios & Testing)

### 사용자 스토리 1 - 주제로 스크립트 생성 (우선순위: P1)

크리에이터는 간단한 주제 아이디어로 비디오 스크립트를 빠르게 생성하기를 원합니다. 그들은 주제 설명을 제공하고, 타겟 플랫폼(Shorts/TikTok/Reels)을 선택하고, 원하는 길이(15/30/60초)를 지정하며, 비디오 유형 프리셋(Explainer/Marketing/Tutorial/Recipe/Story)을 선택합니다. 시스템은 선택한 포맷에 최적화된 전체 내레이션 스크립트를 생성합니다.

**우선순위 선정 이유**: 이것은 모든 비디오 제작 워크플로우의 기초적인 진입점입니다. 스크립트 생성 없이는 다른 어떤 기능도 작동할 수 없습니다.

**독립 테스트**: 주제를 입력하고, 옵션을 설정하고, 생성된 스크립트를 수신하는 것으로 완전히 테스트할 수 있습니다. 거친 아이디어를 구조화된 콘텐츠로 변환하여 즉각적인 가치를 전달합니다.

**인수 시나리오 (Acceptance Scenarios)**:

1. **Given** 크리에이터가 프로젝트 생성 페이지에 있고, **When** 주제 텍스트(최소 10자)를 입력하고, platform="shorts", duration=30, type="Explainer"를 선택한 뒤 "Generate Script"를 클릭하면, **Then** 시스템은 60초 이내에 생성된 스크립트를 표시하고 이를 version 1로 저장한다.
2. **Given** 스크립트 생성이 실패한 경우, **When** 에러가 발생하면, **Then** 시스템은 사용자 친화적인 에러 메시지를 표시하고 "Retry" 버튼을 보여준다.
3. **Given** 크리에이터가 유효하지 않은 길이(>60초)를 입력한 경우, **When** 제출을 시도하면, **Then** 시스템은 "숏폼 콘텐츠의 최대 길이는 60초입니다"라는 유효성 검사 에러를 보여준다.

### 사용자 스토리 2 - 스크립트 빠른 편집 도구 (우선순위: P1)

크리에이터는 생성된 스크립트를 가지고 있지만 선호하는 톤과 길이에 맞춰 다듬고 싶어 합니다. 그들은 원클릭 편집 버튼을 사용하여 스크립트를 빠르게 다시 씁니다: "Shorten(축소)"은 핵심 포인트를 유지하면서 단어 수를 줄이고, "Lengthen(확장)"은 더 많은 세부 정보를 추가하며, "Rephrase(재구성)"는 언어를 더 자연스럽게 만들고, "Change Tone(톤 변경)"은 스타일(Casual/Professional/Funny/Inspirational)을 조정합니다. 각 편집은 사용자가 수락하거나 버릴 수 있는 새로운 스크립트 버전을 생성합니다.

**우선순위 선정 이유**: PRD의 핵심 가치 제안 #1입니다. 크리에이터가 초안을 그대로 수락하는 경우는 드뭅니다. 빠른 편집은 마찰을 줄이고 만족도를 높입니다.

**독립 테스트**: 스크립트를 생성하고, 빠른 편집 변환을 적용하고, 새 버전이 생성되는지 확인하여 테스트할 수 있습니다. 수동으로 다시 쓰는 작업 없이 빠른 반복(iteration)을 가능하게 하여 가치를 전달합니다.

**인수 시나리오**:

1. **Given** 생성된 스크립트가 존재할 때, **When** 크리에이터가 "Shorten"을 클릭하면, **Then** 시스템은 요약된 버전(원래 길이의 70% 목표)을 생성하고 미리보기와 함께 "Apply this version?"을 묻는다.
2. **Given** 요약된 버전이 미리보기 된 상태에서, **When** 크리에이터가 "Apply"를 클릭하면, **Then** 시스템은 이를 새로운 스크립트 버전(v1에서 v2로 증가)으로 저장하고 활성 버전으로 만든다.
3. **Given** 스크립트가 존재할 때, **When** 크리에이터가 "Change Tone"을 클릭하고 "Casual"을 선택하면, **Then** 시스템은 스크립트를 캐주얼한 스타일로 다시 쓰고 "Apply" 옵션과 함께 미리보기를 보여준다.
4. **Given** 크리에이터가 텍스트 영역(textarea)에서 스크립트를 수동으로 편집할 때, **When** "Apply"를 클릭하면, **Then** 시스템은 source="llm" 대신 source="user"인 새로운 버전으로 저장한다.
5. **Given** 스크립트에 여러 버전이 있을 때, **When** 크리에이터가 버전 기록을 보면, **Then** 타임스탬프, 소스 유형(llm/user)이 포함된 모든 버전을 볼 수 있으며 이전 버전을 복원할 수 있다.

### 사용자 스토리 3 - 스토리보드 장면 생성 (우선순위: P1)

크리에이터는 스크립트에 만족하고 이를 시각적인 장면으로 나눈 것을 보고 싶어 합니다. 그들이 처음으로 스토리보드로 이동하면, 시스템은 자동으로 스크립트를 내레이션 텍스트, 초안 길이(duration), 검색 키워드를 포함한 장면들로 분할합니다. 만약 분할 결과 장면이 너무 많으면(60초 비디오 기준 20개 초과), 시스템은 가독성을 유지하기 위해 짧은 장면들을 자동으로 병합합니다.

**우선순위 선정 이유**: 이것은 스크립트와 시각적 스토리보드 사이의 다리 역할을 합니다. 장면 생성 없이는 크리에이터가 비디오 구조를 시각화하거나 편집할 수 없습니다.

**독립 테스트**: 스크립트를 생성하고, "Go to Storyboard"를 클릭한 뒤, 적절한 텍스트/길이/키워드를 가진 장면 카드가 생성되는지 확인하여 테스트할 수 있습니다. 추상적인 텍스트를 구체적인 시각적 계획으로 변환하여 가치를 전달합니다.

**인수 시나리오**:

1. **Given** version=3인 스크립트가 존재할 때, **When** 크리에이터가 "Go to Storyboard"를 클릭하고 존재하는 장면이 없다면, **Then** 시스템은 최신 스크립트로부터 장면을 생성하고, `storyboard_script_version=3`을 저장하며, 그리드 뷰에 장면 카드들을 표시한다.
2. **Given** 장면 생성이 60초 스크립트에 대해 25개의 장면을 생성했을 때, **When** 생성이 20개 장면 초과를 감지하면, **Then** 시스템은 총 장면 수가 20개 이하가 될 때까지 짧은 장면(< 2초)을 인접한 장면과 자동으로 병합한다.
3. **Given** 장면들이 병합될 때, **When** 병합이 발생하면, **Then** 시스템은 내레이션 텍스트를 공백으로 연결하고, 길이(durations)를 합산하며, 첫 번째 장면의 주요 키워드를 유지한다.
4. **Given** 프로젝트에 장면들이 이미 존재할 때, **When** 크리에이터가 다시 스토리보드로 이동하면, **Then** 시스템은 다시 생성하지 않고(1회 생성 정책) 기존 장면들을 불러온다.
5. **Given** 장면이 존재한 후에 스크립트가 편집되었을 때, **When** 크리에이터가 스토리보드로 돌아오면, **Then** 시스템은 "스크립트가 업데이트되었습니다. 장면이 일치하지 않을 수 있습니다. 장면을 재생성하시겠습니까?"라는 배너와 함께 "Regenerate" 및 "Keep existing" 버튼을 보여준다.

### 사용자 스토리 4 - 장면 카드 편집 (우선순위: P2)

크리에이터는 전체 스토리보드를 재생성하지 않고 개별 장면을 미세 조정하기를 원합니다. 그들은 장면 카드를 클릭하여 길이(duration)를 편집하거나, 키워드를 조정하거나, 자막 프리셋을 변경합니다. 변경 사항은 즉시 저장되며 세션 간에 유지됩니다. 크리에이터는 드래그하여 장면 순서를 재배치하고 시각적 흐름을 조정할 수도 있습니다.

**우선순위 선정 이유**: PRD의 핵심 가치 제안 #2입니다. 전체 재생성 대신 타겟 수정(targeted fixes)을 가능하게 하여 시간을 절약하고 좋은 장면을 보존합니다.

**독립 테스트**: 장면을 생성하고, 장면 카드를 클릭하여 길이/키워드/프리셋을 수정하고, 변경 사항이 유지되는지 확인하여 테스트할 수 있습니다. 세밀한 제어를 가능하게 하여 가치를 전달합니다.

**인수 시나리오**:

1. **Given** duration=5초인 장면 카드가 존재할 때, **When** 크리에이터가 카드를 클릭하고 길이를 7초로 변경하면, **Then** 시스템은 `duration_sec_draft=7`로 업데이트하고 즉시 저장한다.
2. **Given** 장면의 primary_keyword="beach"일 때, **When** 크리에이터가 키워드를 "ocean sunset"으로 편집하면, **Then** 시스템은 키워드를 업데이트하고 시각적 확인(체크표시)을 보여준다.
3. **Given** 자막 프리셋(Minimal, Highlight, Karaoke)을 사용할 수 있을 때, **When** 크리에이터가 한 장면에 대해 "Highlight"를 선택하면, **Then** 시스템은 해당 장면에 `subtitle_style_preset_id="highlight"`를 저장한다.
4. **Given** 여러 장면이 존재할 때, **When** 크리에이터가 Scene 3을 위치 1로 드래그하면, **Then** 시스템은 장면 순서를 재배열하고 모든 `order_index` 값을 업데이트한다(Scene 3은 인덱스 0이 되고, 나머지는 이동).
5. **Given** 크리에이터가 다른 장면들에 여러 편집을 수행했을 때, **When** 페이지를 새로고침하거나 나중에 돌아오면, **Then** 모든 변경 사항이 보존되고 올바르게 로드된다.

### 사용자 스토리 5 - 데이터 영속성 및 프로젝트 다시 불러오기 (우선순위: P2)

크리에이터는 여러 세션에 걸쳐 비디오 작업을 수행합니다. 프로젝트를 생성하고, 스크립트를 생성하고, 장면을 편집한 뒤 브라우저를 닫습니다. 나중에 돌아왔을 때, 대시보드에서 프로젝트를 다시 불러와 모든 데이터가 그대로인 상태에서 정확히 중단한 지점부터 계속할 수 있습니다.

**우선순위 선정 이유**: 크리에이터가 한 번에 비디오를 완성하지 않는 실제 사용 환경에 필수적입니다. 영속성 없이는 브라우저 종료 시 모든 작업이 손실됩니다.

**독립 테스트**: 프로젝트를 생성하고, 변경을 수행하고, 브라우저를 닫고, 다시 열어서 프로젝트가 모든 데이터와 함께 다시 로드되는지 확인하여 테스트할 수 있습니다. 다중 세션 워크플로우를 가능하게 하여 가치를 전달합니다.

**인수 시나리오**:

1. **Given** 크리에이터가 topic="AI productivity tips"로 프로젝트를 생성할 때, **When** 프로젝트가 생성되면, **Then** 시스템은 status="draft", 인증된 사용자와 일치하는 user_id, 그리고 타임스탬프와 함께 저장한다.
2. **Given** 스크립트 버전 2와 15개의 장면이 있는 프로젝트가 존재할 때, **When** 크리에이터가 로그아웃하고 다시 로그인하면, **Then** 프로젝트 목록에 제목, 상태, "최종 수정(last modified)" 타임스탬프와 함께 프로젝트가 나타난다.
3. **Given** 크리에이터가 목록에서 프로젝트를 클릭할 때, **When** 프로젝트가 로드되면, **Then** 시스템은 현재 스크립트(최신 버전)와 현재 상태의 모든 장면을 표시한다.
4. **Given** 크리에이터가 다른 상태의 여러 프로젝트를 가지고 있을 때, **When** 프로젝트 대시보드를 보면, **Then** 상태 표시기(draft/rendering/done/failed)와 함께 "최종 수정" 순으로 정렬된 모든 프로젝트를 볼 수 있다.
5. **Given** 프로젝트가 30일 동안 유휴 상태였을 때, **When** 크리에이터가 이를 열면, **Then** 모든 데이터가 보존되어 있으며 시스템은 "Continue editing" 버튼을 제공한다.

### 사용자 스토리 6 - 진행/복구 UX 상태 모델 (우선순위: P3)

**참고**: 이것은 2단계(Phase 2) 준비를 위한 **스펙 전용(SPEC-ONLY)** 항목입니다. 1단계에서는 구현되지 않습니다.

시스템은 비동기 작업 및 복구 워크플로우 추적을 위한 상태 모델을 정의합니다. 렌더링 작업(Render jobs)은 queued -> running -> succeeded/failed/canceled 상태로 진행됩니다. 각 작업은 단계별 진행 상황(TTS 생성, 자막 생성, 미디어 가져오기, 렌더링 합성)을 추적합니다. 실패한 작업은 재시도 진입점과 명확한 에러 메시지를 제공합니다.

**우선순위 선정 이유**: 2단계 렌더링 인프라의 토대를 마련합니다. 지금 상태를 정의하면 나중에 재작업을 방지할 수 있습니다.

**독립 테스트**: 상태 전이를 문서화하고 PRD의 모든 실패/복구 시나리오를 커버하는지 검증하여 테스트할 수 있습니다.

**인수 시나리오**:

1. **Given** 상태 모델 명세서가 있을 때, **When** 검토하면, **Then** queued, running, succeeded, failed, canceled와 같은 모든 작업 상태가 명확한 전이 규칙과 함께 정의되어 있다.
2. **Given** 단계 진행 모델이 있을 때, **When** 검토하면, **Then** 단계별 상태 추적과 함께 tts_generation, subtitle_generation, media_fetch, render_composite 단계가 정의되어 있다.
3. **Given** media_fetch 단계에서 작업이 실패했을 때, **When** 복구 흐름이 문서화되면, **Then** 실패한 단계에서의 재시도, 대체 제공자로의 폴백(fallback), 사용자 업로드 옵션이 명시되어 있다.
4. **Given** 상태 모델이 있을 때, **When** 검토하면, **Then** 모든 작업 상태에 대해 retry_count, error_code, error_message, last_updated 타임스탬프 필드가 포함되어 있다.
5. **Given** 작업이 "running" 상태에서 멈춰있을 때, **When** 지연된 작업 정리(stalled job reaper) 명세서를 검토하면, **Then** 타임아웃 임계값(예: 15분 동안 업데이트 없음)과 복구 조치(실패로 표시 또는 다시 대기열 추가)가 정의되어 있다.

### 엣지 케이스 (Edge Cases)

- 스크립트 생성이 60초 후에 타임아웃되면 어떻게 되는가?
- 시스템은 "Generation timed out. Please retry or try a shorter topic."이라는 에러 메시지를 표시하고, LLM 모델을 전환할 수 있는 옵션과 함께 Retry 버튼을 보여준다.

- LLM API가 형식이 잘못되거나 불완전한 콘텐츠를 반환하면 어떻게 되는가?
- 시스템은 응답의 최소 길이와 구조를 검증한다. 유효하지 않은 경우, "Generated content was incomplete. Please try again."이라는 에러와 함께 Retry 버튼을 보여준다.

- 크리에이터가 이미 장면을 수동으로 편집한 후 장면을 재생성하려고 하면 어떻게 되는가?
- 시스템은 "Regenerating will overwrite your manual scene edits. Continue?"라는 경고를 "Cancel" 및 "Regenerate anyway" 버튼과 함께 보여준다.

- 장면 분할이 매우 긴 1-2개의 장면(각각 15초 이상)만 생성하면 어떻게 되는가?
- 시스템은 이 장면들을 수락하지만(최소 장면 수 없음), "Consider breaking this into shorter scenes for better engagement"라는 제안을 무시 옵션과 함께 표시한다.

- 장면이 이미 존재하는데 크리에이터가 스크립트를 더 길게(예: 30초에서 60초로) 편집하면 어떻게 되는가?
- 시스템은 "Script length changed. Current scene count may be insufficient for new duration. Recommend regenerating scenes."라는 배너를 "Regenerate" 및 "Keep current" 옵션과 함께 표시한다.

- 장면에 대한 키워드 생성이 실패하면 어떻게 되는가?
- 시스템은 프로젝트 주제를 키워드로 대신 사용하거나(fallback), 간단한 NLP 규칙을 사용하여 장면의 내레이션 텍스트에서 첫 번째 명사구를 추출한다.

- 여러 스크립트 버전이 존재하고 크리에이터가 "Regenerate scenes"를 클릭하면 어떻게 되는가?
- 시스템은 **최신** 스크립트 버전에서 생성하고, `storyboard_script_version`을 그에 맞춰 업데이트하며, 이전 장면들은 폐기한다.

- 프로젝트는 생성되었지만 스크립트 생성이 시작되지 않은 경우 어떻게 되는가?
- 프로젝트는 script_version=null인 status="draft" 상태로 유지되며, 프로젝트 목록에 "Incomplete - no script generated"로 나타난다.

- 장면 길이가 수동으로 0, 음수, 또는 최대값을 초과하여 설정되면 어떻게 되는가?
- 시스템은 입력을 검증하고 "길이는 1초부터 [max_duration]초 사이여야 합니다"라는 에러를 보여주며 저장을 방지한다. 여기서 [max_duration] = min(60초, project.target_duration_seconds).
- 모든 장면 길이의 합이 project.target_duration_seconds를 초과하면 어떻게 되는가?
- 시스템은 저장을 차단하고 "전체 장면 길이(X초)가 목표 길이(Y초)를 초과했습니다. 목표 길이 내에 맞추도록 개별 장면 길이를 조정하세요."라는 검증 에러를 표시한다.

- 모든 장면이 수동으로 삭제되는 경우(해당 작업이 존재한다면) 어떻게 되는가?
- 시스템은 "At least one scene is required"라는 에러를 보여주며 마지막 장면의 삭제를 방지하거나 "Regenerate all scenes" 버튼을 제공한다.

- **FR-059**: 시스템은 작업 스냅샷 필드를 정의해야 한다(MUST): 스토리보드 스크립트 버전 스냅샷, 음성 식별자 스냅샷, 스크립트 버전 스냅샷
- **FR-060**: 시스템은 재시도 시도 횟수를 추적하는 재시도 카운트(retry count)를 정의해야 한다(MUST).
- **FR-061**: 시스템은 실패 상태에 대한 에러 코드 및 에러 메시지 필드를 정의해야 한다(MUST).
- **FR-062**: 시스템은 지연된 작업 타임아웃 임계값을 정의해야 한다(MUST) (예: 최종 업데이트 타임스탬프 변경 없이 15분).
- **FR-063**: 시스템은 복구 조치를 정의해야 한다(MUST): 실패한 단계부터 재시도, 제공자 전환, 사용자 업로드, 취소

### 주요 엔티티 (Key Entities)

**Project**

- 주제, 구성 및 현재 상태를 가진 비디오 제작 프로젝트를 나타냄
- 속성: 고유 식별자, 소유자 참조, 제목(주제에서 파생되거나 사용자 정의), 주제(입력 텍스트), 플랫폼 선택(shorts/tiktok/reels), 비디오 유형(Explainer/Marketing/Tutorial/Recipe/Story), 목표 길이 초 단위(15/30/60, 최대 60), 최신 스크립트 버전 참조, 스토리보드 스크립트 버전 참조(장면 생성에 사용됨, 장면 생성 전까지 null), 현재 상태(draft/rendering/done/failed), 생성 타임스탬프, 최종 수정 타임스탬프

**Script**

- 프로젝트의 버전 관리된 내레이션 스크립트를 나타냄
- 속성: 고유 식별자, 소유 프로젝트 참조, 버전 번호(1에서 시작하여 증가하는 정수), 내용(전체 내레이션 텍스트), 소스(생성 방법을 나타내는 llm/user), 생성 타임스탬프

**Scene**

- 스토리보드 내의 단일 시각적 장면을 나타냄
- 속성: 고유 식별자, 소유 프로젝트 참조, 스토리보드 내 위치/순서, 내레이션 텍스트(이 장면에 대한 스크립트 세그먼트), 초안 길이 초 단위(사용자 편집 가능), 최종 길이 초 단위(TTS 이후 결정됨, 1단계에서는 null), 주요 키워드(미디어 매칭을 위한 검색어), 자막 스타일 프리셋 참조, 생성 타임스탬프, 최종 수정 타임스탬프

**RenderJob** (스펙 전용 - 2단계)

- 상태 추적 기능이 있는 비동기 렌더링 작업을 나타냄
- 속성: 고유 식별자, 소유 프로젝트 참조, 상태(queued/running/succeeded/failed/canceled), 현재 처리 단계(tts/subtitle/media/render), 진행률(0-100), 재시도 횟수, 스토리보드 스크립트 버전 스냅샷(작업 시작 시 고정), 음성 식별자 스냅샷(작업 시작 시 고정), 스크립트 버전 스냅샷(감사용), 에러 코드, 에러 메시지, 생성 타임스탬프, 최종 업데이트 타임스탬프

**JobStep** (스펙 전용 - 2단계)

- 렌더링 작업 내의 단일 단계를 나타냄
- 속성: 고유 식별자, 부모 렌더링 작업 참조, 단계 이름(tts_generation/subtitle_generation/media_fetch/render_composite), 상태(pending/running/failed/done), 시작 타임스탬프, 종료 타임스탬프, 로그(에러 상세 또는 상태 노트)

## 성공 기준 (Success Criteria)

### 측정 가능한 결과 (Measurable Outcomes)

- **SC-001**: 사용자는 90초 이내에 프로젝트를 만들고 스크립트를 생성할 수 있다 (주제 입력부터 생성된 스크립트 표시까지)
- **SC-002**: 스크립트 생성 성공률 >= 95% (네트워크/타임아웃 실패 제외)
- **SC-003**: 스크립트 빠른 편집 작업(Shorten/Lengthen/Rephrase/Change Tone)은 작업당 45초 이내에 완료된다.
- **SC-004**: 스크립트로부터 장면 생성은 일반적인 60초 비디오에 대해 10초 이내에 완료된다.
- **SC-005**: 장면 자동 병합은 초기 분할이 20개 장면을 초과하는 경우 100%의 케이스에서 장면 수를 20개 이하로 올바르게 줄인다.
- **SC-006**: 장면 카드 편집은 100%의 케이스에서 올바르게 저장되고 유지된다 (페이지 새로고침 및 프로젝트 다시 불러오기로 검증).
- **SC-007**: 대시보드에서 프로젝트 다시 불러오기는 모든 데이터(스크립트, 장면, 메타데이터)를 3초 이내에 올바르게 표시한다.
- **SC-008**: 사용자는 첫 시도에서 5분 이내에 전체 워크플로우(주제 -> 스크립트 -> 장면 생성 -> 장면 편집)를 완료할 수 있다.
- **SC-009**: 스크립트 대 스토리보드 버전 불일치 감지 정확도 = 100% (버전이 다를 때마다 경고 표시)
- **SC-010**: 브라우저 세션 간 데이터 손실 사고 0건 (다시 불러오기 시 모든 편집 보존)
